Entwicklerzugang erlaubt es Ihrem eigenen R+D-Konto, OAuth-Anwendungen für andere
Nutzer zu registrieren. Persönliche API-Token dienen dagegen Skripten für Ihr eigenes
Konto. Jeder OAuth-Nutzer erteilt Ihrer Anwendung eine eigene Zustimmung.

## Entwicklerportal öffnen

Melden Sie sich mit dem Konto an, das Ihre Apps besitzen soll, und öffnen Sie direkt
`/app/developers`. Die Seite erscheint bewusst nicht in der Dashboard-Navigation.

| Umgebung   | Portal                                                                      | Issuer                                    |
| ---------- | --------------------------------------------------------------------------- | ----------------------------------------- |
| Staging    | [Staging-Portal](https://staging.researchanddesire.com/app/developers)      | `https://staging.researchanddesire.com`   |
| Produktion | [Produktionsportal](https://dashboard.researchanddesire.com/app/developers) | `https://dashboard.researchanddesire.com` |

Verwenden Sie die für Ihre Integration freigeschaltete Umgebung. Ist die Seite nicht
verfügbar, kontaktieren Sie R+D. Entwickleranträge, App-Registrierungen, Kontodaten,
Zugangsdaten und Token sind pro Umgebung getrennt; ein Staging-Test gibt keine Produktions-App frei.

## Antrag vorbereiten

Geben Sie Ihren Entwickler- oder Organisationsnamen, eine HTTPS-Website, eine
Kontaktadresse, eine Beschreibung der Integration, die Datennutzung und die gewünschten
Produkte (Lockbox, DTT und/oder OSSM) an. Beschreiben Sie bei der Datennutzung konkret,
was Sie lesen oder ändern, warum und wie Sie Daten speichern, aufbewahren und löschen.

Ein Beispiel: Eine Beziehungsverwaltung zeigt aktuelle Lockbox-Sitzungen und lässt
berechtigte Schlüsselhalter deren Dauer ändern. Sie speichert eine Sitzungsübersicht
und löscht diese beim Trennen der Verbindung. Ihr Antrag muss Ihre tatsächliche
Umsetzung beschreiben.

Senden Sie den Antrag ab. Status und Rückmeldung finden Sie im Portal. Nach einer
Ablehnung können Sie die Rückmeldung einarbeiten und erneut einreichen. Für die
Bearbeitung wird durch diesen Ablauf keine feste Frist zugesagt.

| Status                  | Verfügbare Möglichkeiten                                       |
| ----------------------- | -------------------------------------------------------------- |
| Entwicklerantrag offen  | Antrag und Status ansehen                                      |
| Entwickler freigegeben  | Bis zu fünf Apps erstellen und konfigurieren                   |
| Erste App-Prüfung offen | Eigentümer und bis zu fünf akzeptierte Tester können verbinden |
| App freigegeben         | Weitere berechtigte R+D-Nutzer können zustimmen                |

Eine Testeinladung genehmigt weder Ihr eigenes Entwicklerkonto noch den Zugriff auf
fremde App-Einstellungen. Weiter: [Erste Anwendung erstellen](/de/build-an-app/first-application).
