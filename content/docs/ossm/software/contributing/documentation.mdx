# Contributing to Documentation

The documentation sites are built with [Fumadocs](https://fumadocs.dev/) in the private `rad-app` monorepo. Public content-only mirrors let community members propose changes without access to the application repository.

<Info>
  Choose the mirror that owns the page: [User
  Guides](https://github.com/researchanddesire/simple-docs), [Open Hardware
  Assembly Instructions](https://github.com/researchanddesire/assembly-docs), or
  [Developer Docs](https://github.com/researchanddesire/dev-docs).
</Info>

## Propose a change

<Steps>
<Step title="Fork the public content repository">
Create a fork of the appropriate mirror and make a focused branch from `main`.
</Step>

<Step title="Edit the content">
  Pages live under `content/` and use Markdown or MDX. Keep images next to the
  pages that use them and use existing Fumadocs components for callouts, cards,
  tabs, accordions, and steps.
</Step>

<Step title="Open a pull request">
  Describe the reader-facing outcome and include screenshots when the rendered
  layout changes.
</Step>

<Step title="Wait for the private-source sync">
After review, automation proposes the approved content in `rad-app`. Changes are deployed only after the private-source pull request passes its checks and is merged.
</Step>
</Steps>

## Local preview

The public repositories intentionally contain content only. Maintainers preview changes from the matching Fumadocs app in `rad-app`:

```bash
pnpm --filter docs-dev dev
```

The same pattern applies to `docs-userguide` and `docs-ohai`.

<Warning>
  Never add application code, credentials, generated build output, or private
  product information to a public documentation mirror.
</Warning>
