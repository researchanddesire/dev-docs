# Présentation du micrologiciel

Le micrologiciel Open Source Sex Machine (OSSM) est un système de contrôle basé sur ESP32 qui gère les mouvements, les entrées de l'utilisateur et la communication de votre appareil. Ce guide vous guide à travers l'architecture du projet et vous aide à configurer votre environnement de développement.

## Technologies de base

Le micrologiciel OSSM s'appuie sur quatre technologies clés qui fonctionnent ensemble pour offrir un contrôle de mouvement réactif et fiable.

<AccordionGroup>
<Accordion title="Machine à états - Boost SML" icon="diagram-project">
[Boost SML](https://boost-ext.github.io/sml/) (State Machine Language) est une bibliothèque C++ en en-tête uniquement qui fournit un langage spécifique au domaine pour définir des machines à états.

**Pourquoi nous l'utilisons :**
- La vérification de la machine d'état au moment de la compilation détecte les erreurs avant l'exécution
- Aucune surcharge d'exécution par rapport aux implémentations manuelles de commutateurs/de cas
- Une syntaxe claire et déclarative rend les transitions d'état complexes lisibles
- Gère les transitions entre les états comme inactif, en cours d'exécution, erreur et référencement

La machine d'état régit les modes de fonctionnement de l'appareil, garantissant des transitions sûres et un comportement prévisible. Pour plus de détails, consultez la documentation [State Machine Architecture](/ossm/software/architecture/state-machine).
</Accordion>

<Accordion title="Affichage - Bibliothèque U8G2" icon="display">
[U8G2](https://github.com/olikraus/u8g2) est une bibliothèque graphique monochrome optimisée pour les systèmes embarqués et les écrans OLED.

**Pourquoi nous l'utilisons :**
- Prend en charge une large gamme de contrôleurs d'affichage, notamment SSD1306 et SH1106
- Empreinte mémoire minimale adaptée à la RAM limitée de l'ESP32
- Rendu de police intégré avec plusieurs tailles et styles
- Dessin accéléré par le matériel pour des mises à jour fluides de l'interface utilisateur

U8G2 restitue l'interface sur l'appareil, y compris la vitesse, la profondeur, la sélection de modèle et l'état du système.
</Accordion>

<Accordion title="Gestion des tâches - FreeRTOS" icon="layer-group">
[FreeRTOS](https://www.freertos.org/) est un noyau de système d'exploitation en temps réel qui permet le multitâche sur les appareils embarqués.

**Pourquoi nous l'utilisons :**
- Exécute plusieurs tâches simultanées (contrôle de mouvement, mises à jour d'affichage, gestion des entrées)
- La planification basée sur les priorités garantit que les tâches de mouvement urgentes s'exécutent de manière fiable
- Communication inter-tâches via des files d'attente et des sémaphores
- Intégré au framework ESP32 Arduino par défaut

FreeRTOS permet au micrologiciel de traiter simultanément les entrées de l'utilisateur, de mettre à jour l'affichage et de maintenir un timing précis du moteur.
</Accordion>

<Accordion title="Contrôle de mouvement - StrokeEngine" icon="wave-pulse">
[StrokeEngine](https://github.com/theelims/StrokeEngine) est une bibliothèque de modèles de mouvement créée par theelims, modifiée pour les exigences spécifiques à OSSM.

**Pourquoi nous l'utilisons :**
- Génère des modèles de mouvement fluides et personnalisables avec une vitesse et une profondeur configurables
- Prend en charge plusieurs types de motifs (constants, aléatoires, oscillants, etc.)
- Gère la rampe d'accélération pour la protection du moteur
- Fournit un réglage des paramètres en temps réel sans interruption du mouvement

StrokeEngine traduit les paramètres utilisateur en commandes de moteur précises, permettant ainsi la variété de modèles de mouvement disponibles dans OSSM.
</Accordion>
</AccordionGroup>

## Commencer

Configurez votre environnement de développement en suivant ces étapes.

### Conditions préalables

Avant de commencer, assurez-vous d'avoir :
- Un ordinateur exécutant Windows, macOS ou Linux
- Git installé sur votre système
- Une connexion internet pour télécharger les dépendances

<Steps>
<Step title="Installer VS Code et PlatformIO">
Téléchargez et installez [Visual Studio Code](https://code.visualstudio.com/), puis ajoutez l'extension PlatformIO.

1. Ouvrir le code VS
2. Accédez au panneau Extensions (Ctrl+Shift+X / Cmd+Shift+X)
3. Rechercher « IDE PlatformIO »
4. Cliquez sur **Installer** et attendez la fin de l'installation.
5. Redémarrez VS Code lorsque vous y êtes invité

<Tip>
Pour des instructions détaillées de configuration de PlatformIO, consultez notre [Guide de configuration de PlatformIO](/ossm/software/getting-started/platformio).
</Tip>
</Step>

<Step title="Cloner le référentiel">
Ouvrez un terminal et clonez le référentiel OSSM sur votre ordinateur local.

<Tabs>
<Tab title="HTTPS">
```bash
git clone https://github.com/KinkyMakers/OSSM-hardware.git
cd OSSM-hardware/Software
```
</Tab>

<Tab title="SSH">
```bash
git clone git@github.com:KinkyMakers/OSSM-hardware.git
cd OSSM-hardware/Software
```
</Tab>

<Tab title="CLI GitHub">
```bash
gh repo clone KinkyMakers/OSSM-hardware
cd OSSM-hardware/Software
```
</Tab>
</Tabs>

<Note>
Si vous envisagez d'apporter des modifications, créez d'abord le référentiel, puis clonez votre fork à la place.
</Note>
</Step>

<Step title="Ouvrez le projet dans VS Code">
Lancez le projet à l'aide de PlatformIO.

1. Ouvrir le code VS
2. Sélectionnez **Fichier > Ouvrir le dossier**.
3. Accédez au répertoire `OSSM-hardware/Software` que vous venez de cloner
4. Cliquez sur **Sélectionner un dossier** (ou **Ouvrir** sur macOS)

PlatformIO détecte automatiquement le fichier `platformio.ini` et configure le projet.

<Check>
Vous devriez voir la barre d'outils PlatformIO apparaître au bas de VS Code avec les boutons de construction, de téléchargement et de surveillance.
</Check>
</Step>

<Step title="Construire et télécharger le firmware">
Compilez le projet et flashez-le sur votre ESP32.

1. Connectez votre carte ESP32 via USB
2. Cliquez sur le bouton **PlatformIO : Build** (icône de coche) pour compiler
3. Une fois la construction réussie, cliquez sur **PlatformIO : Upload** (icône de flèche) pour flasher le firmware.

<Warning>
Assurez-vous de sélectionner le bon port COM si plusieurs périphériques série sont connectés. Vous pouvez configurer cela dans `platformio.ini` ou via le moniteur de périphérique PlatformIO.
</Warning>
</Step>
</Steps>
