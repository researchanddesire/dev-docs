L'OSSM utilise Bluetooth Low Energy (BLE) pour le contrôle et la surveillance sans fil. Vous pouvez créer des applications client qui se connectent à l'OSSM pour envoyer des commandes et recevoir des mises à jour d'état en temps réel.

<Info>
BLE fournit un contrôle sans fil à faible latence avec reconnexion automatique et synchronisation d'état.
</Info>

## Avant de commencer

Pour vous connecter à votre OSSM via BLE, assurez-vous :

- Votre appareil prend en charge Bluetooth Low Energy (BLE 4.0+)
- L'OSSM est sous tension et n'est pas connecté à un autre client BLE
- Vous êtes à environ 10 mètres de l'appareil

## Architecture des services

L'OSSM implémente un service BLE personnalisé avec de multiples caractéristiques organisées en groupes fonctionnels.

### UUID du service principal

```
522b443a-4f53-534d-0001-420badbabe69
```

Les caractéristiques sont organisées par [plages d'espaces de noms](#uuid-namespace-structure)  pour faciliter l'expansion et la découverte.

Utilisez ces caractéristiques pour envoyer des commandes et configurer l'OSSM.

#### Caractéristique de commande principale

| Propriété | Valeur |
| -------- | ----- |

**Format de commande**

```
set:<parameter>:<value>
```

**Commandes disponibles**

| Commande | Paramètre | Plage de valeurs | Description |
| ------- | --------- | ----------- | ----------- |
| `set:speed:<value>` | vitesse | 0-100 | Définir le pourcentage de vitesse de course |
| `set:stroke:<value>` | accident vasculaire cérébral | 0-100 | Définir le pourcentage de longueur de course |
| `set:depth:<value>` | profondeur | 0-100 | Définir le pourcentage de profondeur de pénétration |
| `set:sensation:<value>` | sensation | 0-100 | Définir le pourcentage d'intensité de sensation |
| `set:pattern:<value>` | modèle | 0-6 | Définir le motif de trait (voir [motifs](#pattern-information-characteristics)) |
| `go:simplePenetration` | - | - | Passer en mode pénétration simple depuis le menu |
| `go:strokeEngine` | - | - | Passer en mode moteur de course depuis le menu |
| `go:streaming` | - | - | Passer en mode streaming (expérimental) depuis le menu |
| `go:menu` | - | - | Revenir au menu principal depuis n'importe quel mode |
| `stream:<pos>:<time>` | pos, heure | pos : 0-100, temps : ms | Envoyer une commande de position en mode streaming (expérimental) |

**Format de réponse**

| Réponse | Signification |
| -------- | ------- |
| `ok:<original_command>` | Commande exécutée avec succès |
| `fail:<original_command>` | Échec de la commande (vérifier le format ou l'état actuel) |

<Tip>
Attendez toujours la réponse avant d'envoyer une autre commande. Les commandes sont traitées séquentiellement.
</Tip>

#### Caractéristique de configuration du bouton de vitesse

| Propriété | Valeur |
| -------- | ----- |
| UUID | `522b443a-4f53-534d-1010-420badbabe69` |
| Propriétés | LIRE, ÉCRIRE |
| But | Configurer si le bouton de vitesse physique limite les commandes de vitesse BLE |

**Valeurs de configuration**

| Valeur | Description |
| ----- | ----------- |
| `true`, `1`, `t` | Le bouton de vitesse agit comme limite supérieure (par défaut) |
| `false`, `0`, `f` | Le bouton de vitesse et la vitesse BLE sont indépendants |

<Tabs>
<Tab title="Bouton comme limite (par défaut)">
Lorsqu'elles sont réglées sur `true`, les commandes de vitesse BLE (0-100) sont traitées comme un pourcentage de la position physique actuelle du bouton.

**Exemple** : Bouton à 50%, commande BLE `set:speed:80` → Vitesse effective = 40%

Ce mode fournit une limite de sécurité matérielle que les utilisateurs peuvent contrôler physiquement.
</Tab>

<Tab title="Mode indépendant">
Lorsqu'elles sont réglées sur `false`, les commandes de vitesse BLE (0-100) sont utilisées directement comme valeur de vitesse, ignorant la position du bouton.

**Exemple** : commande BLE `set:speed:80` → Vitesse effective = 80 %

<Warning>
En mode indépendant, les commandes BLE peuvent remplacer le bouton physique. Assurez-vous que votre application met en œuvre des contrôles de sécurité appropriés.
</Warning>
</Tab>
</Tabs>

**Format de réponse**

| Réponse | Signification |
| -------- | ------- |
| `true` ou `false` | Valeur de configuration actuelle |
| `error:invalid_value` | Entrée invalide fournie |


#### Caractéristique de configuration de compensation de latence

| Propriété | Valeur |
| -------- | ----- |
| UUID | `522b443a-4f53-534d-1030-420badbabe69` |
| Propriétés | LIRE, ÉCRIRE |
| But | Configurer si l'OSSM tente de compenser la latence|

**Valeurs de configuration**

| Valeur | Description |
| ----- | ----------- |
| `true`, `1`, `t` | La compensation de latence est active |
| `false`, `0`, `f` | La compensation de latence est inactive (par défaut) |

<Tabs>
<Tab title="Activé">
Lorsqu'il est défini sur `true`, l'OSSM s'attend à recevoir les commandes et les heures exactes du funscript et à ce que les commandes soient envoyées.
avec le même délai entre les commandes que la valeur du temps. En calculant le temps entre les commandes reçues et la variable temps
l'OSSM est capable de déterminer la latence introduite par BLE et de la corriger en modifiant légèrement la vitesse du mouvement.
Si le temps entre les commandes ne correspond pas à la variable intime, cela ne doit pas être activé. Le réglage du tampon est utilisé pour
ajouter du retard à tous les mouvements. Cela donne à l'OSSM le temps de recevoir la commande suivante avant que la précédente ne soit terminée. Cela permet
la suppression de tout retard introduit par des commandes tardives, ainsi que le lissage du mouvement en combinant des mouvements se déplaçant dans la même direction.
Les joueurs Funscript doivent ajouter cette valeur de tampon à leur décalage de lecture et inclure un paramètre supplémentaire pour affiner le décalage de lecture.
pour tenir compte du temps de transmission et de tout retard inhérent au funscript lui-même.
</Tab>

<Tab title="Désactivé">
Lorsqu'il est défini sur `false`, l'OSSM exécutera les commandes dès leur réception. Les commandes arrivées en retard seront exécutées en retard. Commandes
qui arrivent tôt seront exécutés lorsque la commande précédente sera terminée.

</Tab>
</Tabs>

**Format de réponse**

| Réponse | Signification |
| -------- | ------- |
| `true` ou `false` | Valeur de configuration actuelle |
| `error:invalid_value` | Entrée invalide fournie |

#### Caractéristique de configuration WiFi

| Propriété | Valeur |
| -------- | ----- |
| UUID | `522b443a-4f53-534d-1020-420badbabe69` |
| Propriétés | LIRE, ÉCRIRE |
| But | Configurez les informations d'identification WiFi et vérifiez l'état de la connexion |

**Format d'écriture**

```
set:wifi:<ssid>|<password>
```

Le caractère pipe (`|`) est utilisé comme délimiteur entre le SSID et le mot de passe. Cela permet à la fois au SSID et au mot de passe de contenir des deux-points.

**Format de lecture** (JSON)

```json
{
  "connected": true,
  "ssid": "NetworkName",
  "ip": "192.168.1.100",
  "rssi": -45
}
```

Lorsqu'il n'est pas connecté, le champ `ssid` contiendra le dernier SSID enregistré (le cas échéant), `ip` sera vide et `rssi` sera 0.

**Format de réponse**

| Réponse | Signification |
| -------- | ------- |
| `ok:wifi:connected` | Connecté avec succès |
| `ok:wifi:saved` | Identifiants enregistrés, tentative de connexion |
| `fail:wifi:invalid_format` | Format de commande incorrect (délimiteur de canal manquant) |
| `fail:wifi:invalid_ssid` | Longueur du SSID invalide (doit comporter entre 1 et 32 caractères) |
| `fail:wifi:invalid_password` | Longueur du mot de passe invalide (doit comporter entre 8 et 63 caractères) |
| `fail:wifi:connection_failed` | Impossible de se connecter au réseau |
| `fail:wifi:save_failed` | Échec de l'enregistrement des informations d'identification sur NVS |

<Tip>
Les informations d'identification WiFi sont conservées dans un stockage non volatile (NVS) et seront conservées lors des redémarrages de l'appareil. L'appareil tentera de se connecter automatiquement à l'aide des informations d'identification enregistrées au démarrage.
</Tip>

<Warning>
Les informations d'identification WiFi sont transmises en texte brut via BLE. Assurez-vous que vous faites confiance à la connexion et que vous vous trouvez dans un environnement sécurisé lors de la configuration des paramètres WiFi.
</Warning>

**Exemple d'utilisation**

```javascript
// Configure WiFi
const wifiCommand = "set:wifi:MyNetwork|MyPassword123";
await commandChar.writeValue(new TextEncoder().encode(wifiCommand));

// Read the response
const response = await commandChar.readValue();
console.log(new TextDecoder().decode(response)); // "ok:wifi:connected"

// Check WiFi status
const wifiConfigChar = await service.getCharacteristic(
  "522b443a-4f53-534d-1020-420badbabe69"
);
const statusValue = await wifiConfigChar.readValue();
const status = JSON.parse(new TextDecoder().decode(statusValue));
console.log(status);
// { "connected": true, "ssid": "MyNetwork", "ip": "192.168.1.100", "rssi": -45 }
```

### Commandes de streaming (expérimental)

<Warning>
Le streaming de position est expérimental et n’est pas recommandé pour une utilisation générale. Le protocole et le comportement peuvent changer dans les futures mises à jour du micrologiciel.
</Warning>

En mode streaming (`go:streaming`), l'OSSM accepte les commandes de position en temps réel qui permettent une lecture synchronisée avec du contenu externe tel que des funscripts.

#### Commande de position du flux

| Propriété | Valeur |
| -------- | ----- |
| Format | `stream:<position>:<time>` |
| Position | 0-100 (pourcentage de course) |
| Temps | Millisecondes pour atteindre la position cible |

**Exemples de commandes**

```
stream:0:200      # Move to 0% (retracted) in 200ms
stream:100:150    # Move to 100% (extended) in 150ms
stream:50:300     # Move to 50% (mid-stroke) in 300ms
```

**Comment ça marche**

1. Entrez en mode streaming avec `go:streaming`
2. L'OSSM se met en position 0 (complètement rétracté)
3. Envoyer des commandes `stream:<pos>:<time>` pour contrôler le mouvement
4. Le firmware calcule la vitesse requise pour atteindre la position cible dans le temps spécifié
5. Motion utilise une accélération maximale pour une sensation de réactivité

<Note>
La position 0 représente complètement rétractée (origine) et la position 100 représente complètement déployée. Le paramètre de temps indique la durée du mouvement, permettant à l'OSSM de calculer la vitesse appropriée pour une lecture fluide.
</Note>

**Exigences**

- Version du micrologiciel 3.0 ou ultérieure
- OSSM doit être en mode streaming (état : `streaming` ou `streaming.idle`)
- Commandes envoyées via la caractéristique de commande principale

<Tip>
Pour la lecture de funscript, consultez l'outil [Funscript Player](/ossm/software/communication/ble#streaming-mode) qui gère automatiquement le timing et la génération de commandes.
</Tip>

## Émulation Fleshy Thrust Sync (tests uniquement)

<Warning>
Cette fonctionnalité est destinée uniquement aux tests de développement et son utilisation n'est **pas recommandée**. Il nécessite une version spéciale du micrologiciel et pourra être supprimé dans les versions futures.
</Warning>

Le micrologiciel OSSM peut éventuellement émuler le protocole BLE Fleshy Thrust Sync (FTS) pour les tests de compatibilité avec des applications telles que faptap.net. Cette fonctionnalité est désactivée par défaut et nécessite la compilation du firmware avec l'indicateur `PRETEND_TO_BE_FLESHY_THRUST_SYNC`.

### Service FTS

| Propriété | Valeur |
| -------- | ----- |
| UUID du service | `0000ffe0-0000-1000-8000-00805f9b34fb` |
| UUID caractéristique | `0000ffe1-0000-1000-8000-00805f9b34fb` |
| Propriétés | LIRE, ÉCRIRE, NOTIFIER, INDIQUER |

### Format de protocole binaire

FTS utilise un format binaire compact plutôt que des commandes texte :

| Octet | Description | Gamme |
| ---- | ----------- | ----- |
| 0 | Position | 0-180 (uint8) |
| 1 | Octet de poids fort du temps | MSB du temps en ms |
| 2 | Temps octet de poids faible | LSB du temps en ms |

**Mappage de position** : 0 = entièrement rétracté, 180 = entièrement étendu

**Format de l'heure** : entier non signé de 16 bits en gros-boutiste (ordre des octets du réseau)

### Exemple

Pour passer à la position 90 (étendue à 50 %) en 250 ms :

```
Byte 0: 0x5A (90 decimal - position)
Byte 1: 0x00 (250 >> 8 = 0)
Byte 2: 0xFA (250 & 0xFF = 250)
```

<Note>
L'émulation FTS utilise le même mécanisme de streaming sous-jacent que la commande native `stream:pos:time`. L'OSSM doit être en mode streaming pour que les commandes prennent effet.
</Note>

### Pourquoi pas recommandé

- Le protocole FTS est une spécification tierce non contrôlée par le projet OSSM
- Les modifications de protocole dans les applications compatibles FTS peuvent rompre la compatibilité
- Le protocole de streaming OSSM natif (`stream:pos:time`) est préféré pour les nouvelles intégrations
- Cette fonctionnalité existe principalement pour tester la compatibilité avec les écosystèmes FTS existants

## Gestion des connexions

### Publicité

| Paramètre | Valeur |
| ------- | ----- |
| Nom de l'appareil | `OSSM` |
| UUID de service | Service principal + Service d'informations sur les appareils |
| Intervalle de publicité | 20-40 ms (optimisé pour la fiabilité) |
| Redémarrage automatique | La publicité reprend lorsque tous les clients se déconnectent |

### Sécurité

| Paramètre | Valeur |
| ------- | ----- |
| Couplage | "Just Works" (aucune authentification requise) |
| Cryptage | Connexions sécurisées BLE activées |
| Collage | Désactivé (pas de couplage persistant) |

<Note>
L'OSSM utilise le couplage « Just Works » pour faciliter son utilisation. Toute personne à portée de BLE peut se connecter lorsque l'appareil fait de la publicité.
</Note>

### Sécurité de déconnexion

Lorsqu'une connexion BLE est perdue de manière inattendue, l'OSSM réduit automatiquement la vitesse pour éviter un fonctionnement incontrôlable.

**Comportement de décélération :**

1. Connexion perdue détectée
2. **Délai d'une seconde** — permet de brèves interruptions de signal sans déclenchement
3. **Rampe de 2 secondes** — la vitesse diminue de la valeur actuelle à zéro à l'aide de la courbe sinusoïdale d'entrée-sortie facile
4. L'appareil continue à vitesse nulle jusqu'à ce qu'il soit reconnecté ou arrêté manuellement

<Info>
La courbe sinusoïdale facile d'entrée et de sortie offre une décélération douce qui semble naturelle et réduit les contraintes mécaniques. Si la vitesse était déjà nulle au moment de la déconnexion, aucune rampe ne se produit.
</Info>

**Considérations client :**

- Mettre en œuvre une surveillance des connexions pour détecter rapidement les déconnexions
- Envisagez une logique de reconnexion automatique
- Les commandes locales (potentiomètre, encodeur) restent actives pendant et après la déconnexion
- Les utilisateurs peuvent arrêter manuellement via le bouton de vitesse ou appuyer longuement pour un arrêt d'urgence

```javascript Web Bluetooth (JavaScript)
const device = await navigator.bluetooth.requestDevice({
  filters: [{ name: "OSSM" }],
  optionalServices: ["522b443a-4f53-534d-0001-420badbabe69"],
});

const server = await device.gatt.connect();
const service = await server.getPrimaryService(
  "522b443a-4f53-534d-0001-420badbabe69"
);

// Get characteristics
const commandChar = await service.getCharacteristic(
  "522b443a-4f53-534d-1000-420badbabe69"
);
const stateChar = await service.getCharacteristic(
  "522b443a-4f53-534d-2000-420badbabe69"
);
const speedKnobConfigChar = await service.getCharacteristic(
  "522b443a-4f53-534d-1010-420badbabe69"
);
const wifiConfigChar = await service.getCharacteristic(
  "522b443a-4f53-534d-1020-420badbabe69"
);
const patternsChar = await service.getCharacteristic(
  "522b443a-4f53-534d-3000-420badbabe69"
);

// Subscribe to state updates

stateChar.addEventListener("characteristicvaluechanged", (event) => {
  const state = JSON.parse(new TextDecoder().decode(event.target.value));
  console.log("State update:", state);
});

// Configure speed knob behavior (true = knob as limit, false = independent)

// Configure WiFi

console.log("WiFi:", JSON.parse(new TextDecoder().decode(wifiStatus)));

// Send a command
```

```python Python (bleak)
import asyncio
import json
from bleak import BleakClient

SERVICE_UUID = "522b443a-4f53-534d-0001-420badbabe69"
COMMAND_UUID = "522b443a-4f53-534d-1000-420badbabe69"
STATE_UUID = "522b443a-4f53-534d-2000-420badbabe69"
SPEED_KNOB_UUID = "522b443a-4f53-534d-1010-420badbabe69"
WIFI_CONFIG_UUID = "522b443a-4f53-534d-1020-420badbabe69"

def state_callback(sender, data):
    """Handle state update notifications."""
    state = json.loads(data.decode())
    print(f"State update: {state}")

async def connect_to_ossm():
    async with BleakClient("OSSM") as client:
        # Subscribe to state updates
        await client.start_notify(STATE_UUID, state_callback)

        # Configure speed knob behavior
        await client.write_gatt_char(
            SPEED_KNOB_UUID,
            "true".encode()  # Knob acts as upper limit
        )

        # Configure WiFi
        await client.write_gatt_char(
            WIFI_CONFIG_UUID,
            "set:wifi:MyNetwork|MyPassword123".encode()
        )

        # Check WiFi status
        wifi_status = await client.read_gatt_char(WIFI_CONFIG_UUID)
        print(f"WiFi status: {json.loads(wifi_status.decode())}")

        # Send a command
        command = "set:speed:75"
        await client.write_gatt_char(COMMAND_UUID, command.encode())

        # Keep connection alive to receive notifications
        await asyncio.sleep(10)

asyncio.run(connect_to_ossm())
```

## Dépannage

<AccordionGroup>
<Accordion title="La connexion échoue">
**Symptômes** : Impossible de découvrir ou de se connecter à l'OSSM.

**Solutions** :
- Assurez-vous que l'OSSM est sous tension et à portée (~ 10 mètres).
- Vérifiez qu'aucun autre appareil n'est actuellement connecté à l'OSSM
- Redémarrez l'OSSM pour réinitialiser la pile BLE
- Essayez de vous rapprocher de l'appareil
</Accordion>

<Accordion title="Les commandes ne fonctionnent pas">
**Symptômes** : les commandes renvoient `fail:` ou n'ont aucun effet.

**Solutions** :
- Vérifiez que le format de commande correspond exactement à la spécification
- Vérifiez que l'OSSM est dans un état qui accepte les commandes (par exemple, `strokeEngine` ou `simplePenetration`).
- Utilisez d'abord `go:strokeEngine` ou `go:simplePenetration` si vous êtes dans l'état du menu.
- Lisez l'état actuel pour comprendre quelles commandes sont valides
</Accordion>

<Accordion title="Aucune mise à jour de l'état">
**Symptômes** : les caractéristiques de l'état ne sont jamais mises à jour après l'abonnement.

**Solutions** :
- Vérifier que l'abonnement aux notifications a réussi
- Vérifiez que votre bibliothèque BLE prend en charge les notifications
- Assurez-vous de lire les notifications à partir de l'UUID de caractéristique correct
- Essayez de vous déconnecter et de vous reconnecter
</Accordion>

<Accordion title="Réponses invalides">
**Symptômes** : réception de données inattendues ou mal formées.

**Solutions** :
- Assurez-vous de décoder les réponses sous forme de texte UTF-8
- Vérifiez que l'analyse JSON gère correctement le format d'état
- Recherchez les problèmes d'encodage dans votre bibliothèque BLE
</Accordion>
</AccordionGroup>
