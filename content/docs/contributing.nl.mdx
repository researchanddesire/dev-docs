# Draag bij aan technische documentatie

Elke bewerkbare paginatitel en sectiekop heeft een subtiel potlood. Als u het
selecteert, wordt het overeenkomstige Markdown- of MDX-bestand op de exacte
regel geopend in de webeditor van GitHub op `main`.

## Voer een snelle bewerking uit

1. Selecteer het potlood naast de paginatitel of sectie die u wilt verbeteren.
2. Meld u aan bij GitHub als daarom wordt gevraagd.
3. Bewerk de gemarkeerde bron. Als u geen schrijftoegang hebt, maakt GitHub
   automatisch een fork voor u.
4. Selecteer **Wijzigingen voorstellen**, beschrijf de verbetering en open een
   pull request naar `main`.
5. Wacht tot de validatie van de openbare inhoud is voltooid en reageer op feedback van de maintainers.

Na goedkeuring synchroniseert automatisering de byte-identieke inhoud naar de
private applicatierepository en wordt de gerenderde site via het normale
releasetraject uitgerold. Commits met `[docs-sync]` worden genegeerd door de
workflow in de andere richting, zodat de tweerichtingsspiegel niet in een lus
kan raken.

De synchronisatietaken vergelijken na elke overdracht de hashes van de
Git-inhoudsboom. Zo blijven de openbare bestanden op `main` byte-identiek aan de
gerenderde bron en kan een bewerkingslink niet ongemerkt naar de verkeerde regel
verschuiven.

## Kies de juiste opslagplaats

| Gerenderde site                                      | Openbare bron                                                                         | Bewerkbare inhoud |
| --------------------------------------------------- | ------------------------------------------------------------------------------------- | ---------------- |
| [Gebruikershandleidingen](https://docs.researchanddesire.com) | [researchanddesire/simple-docs](https://github.com/researchanddesire/simple-docs) | `content/` |
| [Documenten voor ontwikkelaars](https://dev.researchanddesire.com) | [researchanddesire/dev-docs](https://github.com/researchanddesire/dev-docs) | `content/docs/` |

De applicatie, de Fumadocs-renderer, de API-implementatie, de uitrolinstellingen
en de inloggegevens blijven in de private applicatierepository. Afzonderlijke
API-operatiepagina's worden gegenereerd uit het Dashboard OpenAPI-document en
bieden daarom een link **Meld een probleem met API-documentatie** in plaats van
een misleidend potlood naar de bronregel.

## Schrijf een nuttige bijdrage

- Vermeld het ondersteunde product, de hardwarerevisie, de firmwareversie of het
  API-schema wanneer dat relevant is.
- Koppel technische beweringen aan de implementatie of specificatie waarmee u ze
  hebt geverifieerd.
- Bewaar afbeeldingen naast de pagina die ze gebruikt en verifieer elk relatief pad.
- Hergebruik de bestaande MDX-callouts, kaarten, tabbladen, accordeons en
  stappen.
- Houd elke pull request gericht en neem nooit inloggegevens,
  privéproductinformatie of gegenereerde build-uitvoer op.

Kleine correcties kunnen volledig in GitHub worden uitgevoerd. Voor grotere
wijzigingen kunt u de openbare repository forken en klonen, de `content/`-structuur
bewerken en de Fumadocs Preview-extensie voor VS Code gebruiken voordat u de pull
request opent.
